# S1–S8 functional specification

- **S1 Research & offer intelligence:** measured demand/competition, competitor research using permitted sources, program search, terms/freshness, eligibility, explainable scores and missing-data reporting.
- **S2 Content intelligence:** sources and claim ledger, content brief/angle/hooks, platform-native text, image prompts and video scripts. Product facts require a source or explicit “unverified” label.
- **S3 SEO/blog:** useful article formats, intent mapping, keyword clusters, internal-link suggestions, metadata, valid schema, disclosure and freshness/decay work queue. Avoid thin mass publishing.
- **S4 Offers/landing:** substantiated value ladders, actual bonus deliverables, landing/lead forms, proof/claim status, CTA, consent/disclosure and versioned review.
- **S5 Distribution/nurture:** provider-authorized CMS/social/email adapters, scheduling, rate limits, retries, idempotency, suppression, remote ID/state reconciliation and publication pause controls.
- **S6 Measurement:** click IDs/UTMs, provider postbacks, pending/approved/reversed/paid event history, experiment assignments and campaign reporting.
- **S7 Operations:** resource reservations, usage accounting, budget ceilings, retries, workers, alerts and emergency stop.
- **S8 Performance memory:** data freshness and sample-size checks, reviewed hypotheses, RAG memory separated from model fine-tuning, independent evaluation and reversible promotion.

A stage is “completed” only when its own operation finished. It does not automatically prove external publication, conversion, profit, approval or cash receipt. Skips and missing prerequisites must be visible.
