# OmniAffiliateOS v4 requirement contract

This is the repository-local engineering contract distilled from the user-provided build prompt, affiliate OS requirements, branch audit, provider matrix and acceptance expectations. It is a navigable implementation contract, not a byte-for-byte archive of every attached file. The uploaded source archives remain external reference artifacts.

Read in order: `00_ACCEPTED_ENGINEERING_CONTRACT.md`, `01_PRODUCT_REQUIREMENTS.md` through `13_RESET_RUNBOOK_GITHUB_STATE.md`, then `../REQUIREMENTS_TRACEABILITY_MASTER.md` and `../skill-parity-matrix.csv`.

## Hard rules

- Code and evidence outrank mock screenshots. A config value, test declaration, directory entry or status string is not proof of a live provider connection.
- Never mark a test PASS unless it actually ran successfully on a named commit.
- Never bypass provider rules, account approval, KYC, rate limits, CAPTCHA, OAuth scopes, disclosure, privacy or consent to achieve “autopilot”.
- Paid spend, external publication, email sends, affiliate applications and payout actions must have their own authorization, budget/policy checks, audit records and idempotency.
- Public repository: no credentials, customer data, private model weights or non-licensed source bundles. Review all imported licenses.
- Earnings goals are hypotheses for measured experiments, not guarantees.
